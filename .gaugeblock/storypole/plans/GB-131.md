# Task Plan: GB-131 — Extract gaugeblock-git Porcelain and Standardize codegen-units for Release Compilation

> **Task Key:** `GB-131`  
> **Parent Epic:** `GB-128`  
> **Scope:** `workspace`  
> **Status:** Planned

---

## 1. Problem Statement
`outfeed-core` has a 99.2% clone between single-repo and suite release tagging, and 4 tools duplicate git subprocess wrappers. Furthermore, all 10 repositories set `[profile.release] codegen-units = 1`, forcing LLVM to serialize to a single CPU core and slowing release compilations by 3x–5x.

---

## 2. Technical Blueprint
1. In `gaugeblock/common/crates/gaugeblock-git`:
   * Implement robust git porcelain helpers: `get_current_branch`, `is_working_tree_dirty`, `get_head_sha`, `create_commit_and_tag`.
   * Implement single-round-trip pushing (`push_branch_and_tag` -> `git push <remote> <branch> <tag>`).
2. In all 10 repository root `Cargo.toml` files:
   * Remove `codegen-units = 1` from `[profile.release]` (allowing default 16), or define a dedicated `release-dist` profile for CI packaging while keeping local release compilation multi-threaded.

---

## 3. Execution Steps
* **Step 1:** Implement git porcelain helpers in `gaugeblock-git`.
* **Step 2:** Standardize `[profile.release]` codegen-units across all 10 root Cargo.toml files.
* **Step 3:** Tier 3 workspace verification (`cargo nextest run --workspace`).

---

## 4. Dependency on `GB-126`

This ticket is `BlockedBy` **`GB-126`**: the outfeed-local 99.2% commit/tag clone must already be
collapsed into a single `outfeed_core::git::create_annotated_commit_and_tag` helper before it is lifted
into `gaugeblock-git`. Do not re-implement the in-crate dedup here — only generalize and relocate it.
