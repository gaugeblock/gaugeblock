# Task Plan: GB-122 — Implement Adaptive Disk Space Headroom Guard and Cache Retention in outfeed

> **Task Key:** `GB-122`  
> **Parent Epic:** `GB-121`  
> **Scope:** `outfeed-core`  
> **Status:** Planned

---

## 1. Problem Statement
`clean_between_repos` currently defaults to `true`, wiping `target/debug` after every released repository. This forces all 10 tools to recompile `syn`, `tokio`, `serde`, and uncached proc-macros from scratch, adding 30–50 minutes of pure CPU churn. If disabled, `outfeed` artificially demanded 20.0 GB of free disk, failing on systems with 12 GB free despite the shared target directory plateauing at only ~5.0 GB.

---

## 2. Technical Blueprint
1. In `outfeed-core/src/model/options.rs`:
   * Change `ReleaseOpts.clean_between_repos` default to `false`.
2. In `outfeed-core/src/suite_check.rs`:
   * Change required headroom threshold to `DEFAULT_MIN_SUITE_DISK_BYTES` (4.0 GB) regardless of `clean_between_repos`.
3. In `outfeed-core/src/suite_exec.rs`:
   * Add continuous `get_available_disk_space()` monitoring before/after every repository release.
   * If available disk `< 3.5 GB`: trigger adaptive surgical pruning of test binaries in `target/debug/deps` using `prune_workspace()`.
   * If available disk `< 2.0 GB`: trigger emergency target clean.
4. In `.cargo/config.toml`:
   * Add `[env] SCCACHE_CACHE_SIZE = "15G"` to prevent LRU cache eviction thrashing.

---

## 3. Execution Steps
* **Step 1:** Modify default options in `options.rs` and preflight threshold in `suite_check.rs`.
* **Step 2:** Implement continuous adaptive headroom guard in `suite_exec.rs`.
* **Step 3:** Add `SCCACHE_CACHE_SIZE` configuration to `.cargo/config.toml`.
* **Step 4:** Tier 2 verification (`cargo nextest run -p outfeed-core`).
