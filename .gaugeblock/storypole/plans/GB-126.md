# Task Plan: GB-126 — Unify AST Structural Clones, Eliminate Redundant Re-planning, and Modularize Files Over 200 LOC

> **Task Key:** `GB-126`  
> **Parent Epic:** `GB-121`  
> **Scope:** `outfeed-core`  
> **Status:** Planned

---

## 1. Problem Statement
`execute_suite_plan()` currently discards `entry.plan` calculated in Phase 2 and calls `plan_release()` a second time in Phase 3, duplicating Git log queries and LLM synthesis. Furthermore, `miter clones` detected a 99.2% AST structural clone between `git.rs:176` and `suite_release.rs:126`, and `miter audit` flagged 9 files exceeding 200 LOC.

---

## 2. Technical Blueprint
1. In `outfeed-core/src/suite_exec.rs`:
   * Pass `entry.plan.as_ref()` into `apply_release_with_progress()` to reuse pre-calculated diffs and changelogs.
2. In `outfeed-core/src/git.rs` & `outfeed-core/src/suite_release.rs`:
   * Extract unified `create_annotated_commit_and_tag(repo_dir, version, message)` helper to eliminate the 99.2% clone.
3. In `outfeed-core/src/clean.rs` & `outfeed-core/src/semver.rs`:
   * Apply `miter slice` blueprints to split `clean.rs` (into `clean/dir_size.rs`) and `semver.rs` (into `semver/parse_commit.rs`), keeping all files strictly under 250 LOC.

---

## 3. Execution Steps
* **Step 1:** Pass Phase 2 ReleasePlan into Phase 3 execution loop.
* **Step 2:** Unify git commit and tagging clone in `git.rs` and `suite_release.rs`.
* **Step 3:** Apply `miter slice` extractions on `clean.rs` and `semver.rs`.
* **Step 4:** Tier 2 verification (`cargo nextest run -p outfeed-core`).
