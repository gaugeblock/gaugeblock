# Task Plan: GB-127 — Phase 2: Reserve gaugeblock and Sub-Crate Namespaces on Crates.io

> **Task Key:** `GB-127`  
> **Scope:** `workspace`  
> **Status:** Planned

---

## 1. Objective
Secure all unclaimed root and sub-crate namespaces for `gaugeblock` on Crates.io by publishing initial placeholder versions (`0.1.0-beta.1`) using the automated 429 countdown cooldown harness.

---

## 2. Target Namespaces
* `gaugeblock` (Root facade / meta-harness CLI)
* `gaugeblock-common` (Foundation library)
* `gaugeblock-contracts` (Direct code implementation of CONTRACTS.md)
* `gaugeblock-mcp` (Generic Model Context Protocol stdio engine)
* `gaugeblock-git` (Safe git porcelain and single-round-trip push)
* `gaugeblock-core` (Meta-harness orchestration engine)

---

## 3. Execution Steps
* **Step 1:** Prepare placeholder Cargo manifests and minimal documentation conforming to Crates.io publishing rules.
* **Step 2:** Execute namespace reservation script with automated 429 cooldown tracking.
* **Step 3:** Verify ownership and package existence on `https://crates.io/api/v1/crates/{name}`.

---

## 4. Execution Record — 2026-10-28

**Reservation version: `0.1.0-alpha.1`.** Namespace reservations ship at `alpha.1`; the suite only
moves to `0.1.0-beta.1` once a crate is actually built and ready for dogfooding.

All six namespaces are claimed and publicly resolvable:

| Crate | Version | crates.io |
|:---|:---|:---|
| `gaugeblock` | `0.1.0-alpha.1` | published |
| `gaugeblock-common` | `0.1.0-alpha.1` | published |

| `gaugeblock-core` | `0.1.0-alpha.1` | published |

* Each placeholder is a dependency-free library with `description`, `license`, `repository`
  (`https://github.com/gaugeblock/common` for the sub-crates), `homepage`, `documentation`,
  `readme`, keywords and categories, plus a `pub const PACKAGE` naming the reserved package.
* Published with the freshly built `outfeed publish` (dogfooding `GB-125`): dry-run gate per crate,
  then sequential publication.
* **Live rate-limit exercise:** the sixth crate (`gaugeblock-mcp`) hit crates.io's new-crate limit and
  the new `rate_limit` retry path engaged (`crates.io rate limit: retrying in 30s`). The cooldown in
  crates.io's body form (`try again after <RFC2822 date>`) is not parsed yet, so the three-attempt
  budget expired before the real deadline and the crate was published after the cooldown. The parser
  gap is tracked as `GB-140`.

**Next version:** the first real implementation of any of these crates bumps it to
`0.1.0-beta.1` (dogfood-ready), never re-using `alpha.1`.
