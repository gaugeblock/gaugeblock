# GB-261 — Consolidate all legacy tool state into `.gaugeblock`

**Status:** plan, awaiting the Phase 0 decision on `D1` before any move is executed.
**Rule this must not break:** nothing is deleted until its bytes exist somewhere tracked, and no
derived cache is ever migrated.

## 2. The tool is not the answer today (`GB-262`)

`benchwork migrate --dry-run`, verbatim:

```
Migrated items: 1
  - [DRY RUN] Would archive .gaugeblock/docs.toml -> ./.gaugeblock/docs.bak.1793995267318
```

One item, and it is wrong: `.gaugeblock/docs.toml` is live canonical config (`GB-256` fixed the nested
`[docs.docs.*]` table in it). It sees **none** of the ten `.storypole/` directories or `miter/.miter/`,
despite help text promising those. **`benchwork migrate` is not run in this epic.** Alert problem is
`GB-255`; detection and false-positive problem is `GB-262`. Migration is by hand, phase by phase,
because the inventory is small and the failure modes are silent.


## 3. Decisions

**D1 — where does per-repo storypole state live?** *(blocks execution)*
Ten different `config.toml` files each carry that repository's ticket prefix and allowed repos/crates.
They cannot merge into one file without losing nine identities.

- **Option A (recommended):** `<repo>/.gaugeblock/storypole/{config.toml, plans/}` — preserves identity,
  matches per-repo resolution, keeps each config in its own repository's history.
- **Option B:** one canonical config at the meta-harness root with per-repo sections. Single source, but
  changes the schema and every loader, and moves repo-scoped settings out of the repos that own them.
- **Option C:** collapse to one suite prefix. **Rejected** — destroys namespaces that already exist.

Everything below assumes **A**.

**D2 — plans.** `<repo>/.storypole/plans/*.md` → `<repo>/.gaugeblock/storypole/plans/`. Law 11 still
satisfied: documents stay committed, in the repository that owns them.

**D3 — `index.sqlite*`.** Delete, never copy. Derived from the ledger; a migrated cache lies after the
first append.

**D4 — `miter/.miter/config.toml`.** `diff` against `.gaugeblock/miter/config.toml`. Identical → delete.
Different → `miter/.gaugeblock/miter/config.toml` under the same rule as D1.

**D5 — stale backups.** Diff against the live file; preserve only content absent from live config, into
`.gaugeblock/config-archive/`. Otherwise delete.

**D6 — out of scope:** `spool/`, `worktrees/`, `datasets/`, `.env`, `storypole/ledger.jsonl`,
`storypole/ledger-archive/`, `miter/miter.redb`, `chat/threads.jsonl`.

## 4. Execution phases

**Phase 0 — probe resolution (no mutation).** Determine whether `storypole`, run with a per-repo
`.gaugeblock/storypole/config.toml` and no local ledger, (a) reads that config and (b) creates a *local*
ledger. If it creates one, a per-repo move forks the backlog and D1 must be re-decided first.
**Gate: answered in writing on this ticket before Phase 1.**

**Phase 1 — one repository end to end.** `rabbet` (no plans, lowest blast radius). Move `config.toml`,
delete `index.sqlite*` and `.gitignore`, `git rm` the empty `.storypole/`, commit. Then `storypole list`
inside `rabbet` and at the root. **Gate: both return the same backlog, and `rabbet`'s prefix is `RB`.**

**Phase 2 — the nine remaining repos**, one commit each, same gate. Repos with plans (`benchwork`,
`outfeed`, `storypole`, `chalkline`) also get a checksum comparison of every `*.md` at its new path.

**Phase 3 — miter** (D4), after the diff.
**Phase 4 — stale backups** (D5).

**Phase 5 — verification.** `miter deps --layers --check`, `storypole ledger-reconcile`,
`outfeed lockfiles`, `chalkline docs check -d <repo>` per touched repo, plus a `find` proving zero
`.storypole/` remain.

## 5. Rollback

Per-repo and per-commit, so rollback is `git revert <sha>` in one repository. Nothing is deleted whose
bytes are not in git history or in `.gaugeblock/storypole/ledger-archive/`. `index.sqlite*` is the sole
exception and is a cache.

## 6. Acceptance criteria

1. Zero `.storypole/` directories, zero legacy ledgers.
2. Every repository's `ticket_prefix` still resolves to its own value.
3. All ten design documents present at `<repo>/.gaugeblock/storypole/plans/`, checksums unchanged.
4. `storypole list` at the root returns the same task count before and after (175 at plan time).
5. No derived cache migrated; nothing deleted that is absent from git history.

## 7. Correction (2026-11-06, after probing per repo)

The §2 conclusion was drawn from a dry-run at the **suite root**, which is the one repository with no
legacy directories. Run inside each repository, `benchwork migrate --dry-run` is correct and complete:

```
rabbet     -> Would move .storypole -> .gaugeblock/storypole
benchwork  -> Would move .storypole -> .gaugeblock/storypole
miter      -> Would move .storypole -> .gaugeblock/storypole
              Would move .miter     -> .gaugeblock/miter
outfeed    -> Would move .storypole -> .gaugeblock/storypole
```

So the tool is **repo-scoped by design**, and `GB-262`'s "sees neither" half was my misreading. The
revised conclusion: **do not hand-migrate. Use the tool per repository**, which is also the dogfooding
the suite exists for — eleven real legacy layouts are the acceptance test, and a hand-migration would
destroy that corpus and leave the tool unexercised.

Remaining real gaps, and the only tool work this epic needs:

1. **Derived caches must not travel.** The dry-run proposes moving the whole directory, and
   `<repo>/.storypole/` contains `index.sqlite`, `index.sqlite-shm`, `index.sqlite-wal`. A stale index
   arriving in `.gaugeblock/storypole/` is worse than no index: it will be opened and it will be wrong.
   Either the engine excludes them or deletes them after the move. **Verify before Phase 1.**
2. **Root-repo `docs.toml`.** Archiving it is defensible (docs config consolidating into
   `.gaugeblock/config.toml`) but the dry run says "archive", not "merge", and says nothing about what is
   preserved. Must be confirmed as a merge, or gated.
3. **Dry-run detail (`GB-255`).** It names source and destination but not per-item classification
   (config → move, plans → move, cache → discard) or conflict handling. That is the alert improvement,
   and it is what makes Phase 2 reviewable across nine repos.

Phase order therefore changes: **0 (done) → 0.5 verify cache handling → 1 rabbet with the tool → 2 the
other nine with the tool → 3 root `docs.toml` decision → 4 verification.**

6. `benchwork migrate` untouched by this work; `GB-262` records why.
