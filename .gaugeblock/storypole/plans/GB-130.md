# Task Plan: GB-130 — Extract gaugeblock-mcp to Eliminate Duplicate JSON-RPC Boilerplate Across 7 MCP Servers

> **Task Key:** `GB-130`  
> **Parent Epic:** `GB-128`  
> **Scope:** `workspace`  
> **Status:** Planned

---

## 1. Problem Statement
`miter clones` detected 100% structural clones across all 7 MCP servers in the suite (`benchwork-mcp`, `outfeed-mcp`, `batten-mcp`, `joiner-mcp`, `miter-mcp`, `storypole-mcp`, `chalkline-mcp`). Each independently re-implements `run_stdio_server`, JSON-RPC 2.0 dispatch, and schema registration (`list_tools`), duplicating over 1,200 lines of boilerplate.

---

## 2. Technical Blueprint
1. In `gaugeblock/common/crates/gaugeblock-mcp`:
   * Define the `McpToolHandler` trait (`list_tools(&self) -> Vec<Value>`, `call_tool(&self, name: &str, args: Value) -> Result<Value, McpError>`).
   * Implement `run_mcp_stdio_server<H: McpToolHandler>(handler: H, name: &str, version: &str) -> Result<(), McpError>`.
   * Implement standard JSON-RPC 2.0 error mapping and tracing instrumentation.
2. Refactor member MCP servers to implement `McpToolHandler` and delegate the event loop to `gaugeblock-mcp`.

---

## 3. Execution Steps
* **Step 1:** Implement `McpToolHandler` trait and generic stdio loop in `gaugeblock-mcp`.
* **Step 2:** Refactor `outfeed-mcp` and `storypole-mcp` to consume `gaugeblock-mcp`.
* **Step 3:** Refactor remaining 5 MCP servers.
* **Step 4:** Tier 3 workspace verification (`cargo nextest run --workspace`).
