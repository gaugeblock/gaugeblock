## 1. Why this exists — four blind spots, each visible in the tree today

| Blind spot | What the tree shows |
|:--|:--|
| No cross-process record of anything | `outfeed gate` prints one line per step (`GateStepResult { name, passed, skipped, detail }`) and discards the duration it could have measured. A 40 s `clippy` and a 0.4 s `docs` look identical afterwards. |
| `benchwork` sees only itself | `BenchworkState.event_tx: broadcast::Sender<LiveEvent>` carries six variants, all produced *inside the daemon*. An MCP tool call from Cline, or a `cargo clippy` spawned by the gate, is invisible. |
| MCP tool usage is unmeasured | `common/crates/gaugeblock-mcp/src/stdio.rs` (139 LOC) routes every one of the seven servers through `dispatch`/`dispatch_async`. Nothing records which tool ran, for how long, or whether it errored. |
| LLM cost is not attributable | `InferenceResponse` already carries `prompt_tokens`, `completion_tokens`, `latency_ms`, `model_used` and `reasoning_tokens` — and every consumer drops them at the return statement. |

The result is that law 12 ("a figure that lives only in chat has not been recorded") is currently
unenforceable at the process level: there is nowhere to read a number from.

## 2. Decisions (resolved on the ticket)

| # | Decision | Chosen | Category |
|:--|:--|:--|:--|
| D1 | Transport for span emission | POSIX `O_APPEND` file-backed flight recorder, zero network coupling | `transport` |
| D2 | Where instrumentation lives | Three shared choke points only | `architecture` |
| D3 | Parent-child correlation across processes | `GAUGEBLOCK_TRACE_ID` / `GAUGEBLOCK_PARENT_SPAN_ID` env vars | `correlation` |
| D4 | How `benchwork` ingests and serves | `notify` watcher + byte offset + SQLite (WAL) index + SSE/REST | `ingestion` |


### D1 — POSIX `O_APPEND` file-backed flight recorder, zero network coupling

CLI binaries and `*-mcp` stdio servers MUST NOT make blocking HTTP/IPC calls to `benchwork`
(`:4242`) to emit telemetry. Every process appends single-line `TelemetrySpan` JSON records
directly to `<canonical_gaugeblock>/telemetry/events.jsonl` using
`OpenOptions::new().create(true).append(true)` (target `< 100 µs`, fails silently if the disk is
read-only).

*Why not HTTP:* a blocking POST inside the MCP request path adds daemon latency to every tool call
and converts a `benchwork` outage into an MCP outage for Cline and Antigravity. Hiding that latency
on a detached thread adds teardown risk on `SIGKILL` — the process that loses the span is exactly
the one that died, which is the case the recorder exists for.

*Why `O_APPEND` is sufficient:* a single `write` of a line at or below `PIPE_BUF` is atomic under
POSIX and lands at the end of the file without a lock, so N concurrent processes append without
interleaving. It needs no daemon, no discovery, no port, no authentication, and it behaves
identically for a CI run nobody is watching.

`.gaugeblock/telemetry/` is added to the root `.gitignore` alongside `.gaugeblock/spool/` and
`.gaugeblock/datasets/`. Note that the existing `.gaugeblock/**/*.sqlite` rule already covers
`telemetry/index.sqlite`; `events.jsonl` and `snapshots/*.diff` are the two paths that need the new
directory rule.

### D2 — Three choke-point instrumentation strategy

Rather than instrumenting individual domain functions across ten repositories, instrument strictly
at three shared choke points:

1. **`gaugeblock-mcp` JSON-RPC request dispatcher** (`SpanKind::McpTool`). Measured: `stdio.rs`
   holds `dispatch()` and `dispatch_async()`, the single routing pair all seven servers share, so
   one wrap covers every VS Code tool call from Cline and Antigravity.
2. **A CLI top-level `SpanGuard` RAII drop helper in `gaugeblock-workspace`**
   (`SpanKind::CliCommand`), plus `SpanKind::GateStep` inside `outfeed gate`'s step runner, which
   already owns the spawn.
3. **`sawhorse-core` provider completion boundary** (`SpanKind::LlmInference`) —
   `RoleRouter::complete` and `complete_stream`, where `InferenceResponse` is in hand.

A `tracing-subscriber` layer was rejected: it would require all eleven binaries to adopt a
subscriber and a shared registry, and it cannot express "one completed span with a duration and an
exit code" as a single appendable line.

### D3 — 3-tier context and parent-child span correlation

Propagate parent-child causality across subprocess boundaries (`outfeed gate` spawning
`cargo clippy`, `miter` and `chalkline`; `joiner fill` invoking `sawhorse`) via
`GAUGEBLOCK_TRACE_ID` and `GAUGEBLOCK_PARENT_SPAN_ID` environment variables, set on the `Command`
and therefore inherited by every child. Environment is the only channel a stdio MCP server and a
spawned `cargo` process both see; W3C `traceparent` needs an HTTP hop the gate does not have.

Automatically enrich every span with `task_key` and `worktree` inferred from `GAUGEBLOCK_TASK_KEY`
or the active git branch / worktree path (`feat/gb-...`), so a span from a linked worktree
attributes to the right task without the caller passing anything.

### D4 — Live tailer and derived SQLite index in `benchwork`

`benchwork-core` watches `.gaugeblock/telemetry/events.jsonl` via the `notify` crate (tracking the
byte offset so a restart resumes instead of replaying), indexes spans into
`.gaugeblock/telemetry/index.sqlite` (WAL mode) for historical law 12 P50/P95 duration and token
queries, and broadcasts new spans immediately over `GET /api/v1/telemetry/stream` (SSE).

Polling re-reads data that has not changed and still adds up to a second of latency to a pulse the
header is meant to animate. Reading the JSONL per request makes P50/P95 a full scan of a file that
grows for the life of the checkout. The index is derived state: gitignored, deletable, and
rebuildable from the JSONL at any time (`rusqlite 0.40 bundled` already matches `storypole-core`
and `rabbet-core`).

## 3. Wire contract — `common/crates/gaugeblock-contracts/src/telemetry/`

> **Path correction (measured, not assumed).** The mission brief names
> `gaugeblock-contracts/src/telemetry.rs` at ≤ 140 LOC. That file already exists at **146 LOC** and
> already owns `TelemetryTier`, `AnonymizedSynthesisTrace`, `SyncStatus`, `SpoolEntry` and
> `SpoolEntry::hash_trace` — the GB-182 spool envelope. Adding the span types inside it would put it
> over 200 and one deserialisation test away from the hard 250 ceiling. **So the module becomes a
> directory**, exactly as `storypole-core/src/telemetry/mod.rs` already does: `telemetry/mod.rs`
> re-exports, `telemetry/spool.rs` carries today's 146 lines unchanged, `telemetry/spans.rs` holds
> the new span wire contract. `pub use telemetry::*;` in `lib.rs` keeps every existing import path
> working, so this is a move, not a breaking change.

```rust
// telemetry/spans.rs — new file, ≤ 140 LOC
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SpanKind {
    CliCommand,
    McpTool,
    GateStep,
    LlmInference,
    AstPass,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SpanStatus {
    Running,
    Ok,
    Error,
    Skipped,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TokenUsageSummary {
    pub model: String,
    pub prompt_tokens: u32,
    pub completion_tokens: u32,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TelemetrySpan {
    pub trace_id: String,
    pub span_id: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub parent_span_id: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub session_id: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub task_key: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub worktree: Option<String>,
    pub binary: String,
    pub kind: SpanKind,
    pub name: String,
    pub started_at_ms: u64,
    pub duration_ms: u64,
    pub status: SpanStatus,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub exit_code: Option<i32>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub token_usage: Option<TokenUsageSummary>,
    /// Scrubbed, compact JSON summary of MCP tool arguments or CLI flags (≤ 512 bytes).
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub input_summary: Option<String>,
    /// Populated on `SpanKind::GateStep` when `status == Error`: first compiler/clippy/doc diagnostic.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub first_diagnostic: Option<String>,
    /// Populated on `SpanKind::GateStep`: content-addressed hash of `git diff HEAD`
    /// (or a spool snapshot key).
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub worktree_diff_hash: Option<String>,
    #[serde(default, skip_serializing_if = "BTreeMap::is_empty")]
    pub attributes: BTreeMap<String, String>,
}
```

Contract invariants:

1. `SpanKind` and `SpanStatus` are `Copy` and `snake_case` on the wire, so a TS discriminant in
   `benchwork/web` is a literal union (`'cli_command' | 'mcp_tool' | ...`) and not a stringly check.
2. Every optional field is `skip_serializing_if`, so a successful span writes ~14 fields. A
   successful `cargo fmt` step must not carry a `first_diagnostic` key at all — `null` and "absent"
   are different things to a dataset builder.
3. **The envelope stays flat and appendable.** No nested span trees: tree shape is reconstructed by
   `parent_span_id` at read time (D4's index, `GB-244`'s miner). A writer must never need to read
   the file back.
4. `started_at_ms` is epoch milliseconds and `duration_ms` is elapsed, not `ended_at`. A reader that
   computes `started_at + duration` gets the end; a clock that jumps backwards cannot make an
   interval negative.
5. `TelemetrySpan` is *not* `PartialEq`: `attributes` ordering is `BTreeMap` so it could be, but
   equality on a struct with a populated token block invites tests that assert on token counts the
   provider never guaranteed. Tests assert field by field.

## 5. Choke points in detail

### 5.1 `SpanGuard` — the only writer

```rust
// gaugeblock-workspace/src/telemetry.rs
pub struct SpanGuard { /* trace_id, span_id, kind, name, binary, started: Instant, ctx, status */ }

impl SpanGuard {
    /// Opens a span. Never fails: an unusable telemetry path yields a guard that writes nothing.
    pub fn start(kind: SpanKind, name: impl Into<String>) -> Self;
    /// Emits children with this span as parent (used by the gate step runner).
    pub fn child(&self, kind: SpanKind, name: impl Into<String>) -> Self;
    /// Records the terminal status/code; `Drop` writes the line.
    pub fn finish_with_status(self, status: SpanStatus, exit_code: Option<i32>) -> Self;
    /// The environment a child process must inherit (D3).
    pub fn export_env(&self) -> [(String, String); 2];
}

impl Drop for SpanGuard { /* one append, fail-open, never panics */ }
```

Rules the guard must hold, each a test:

1. **Fail-open.** A read-only or missing directory produces a no-op guard. Telemetry must never
   change an exit code — the first time a flight recorder breaks a gate is the last time it is
   trusted.
2. **No panic in `Drop`.** A panic during unwinding is an abort; every fallible step is `if let Ok`.
3. **One line per span.** The buffer is built with `serde_json::to_vec` and written with a single
   `write_all` of `json + b"\n"` — never two writes, or two processes can interleave mid-line.
4. **`finish_with_status` before `Drop` wins.** Explicit finish sets the status; `Drop` only writes
   if it has not already, or a `?`-early-return path would write `Running` for a failed command.
5. **Lazy identity.** `trace_id` is inherited from `GAUGEBLOCK_TRACE_ID` when present, otherwise
   generated once per process — so two `miter` calls in one session share a trace but two CLI runs
   do not.

### 5.2 `gaugeblock-mcp` dispatcher (`SpanKind::McpTool`)

`stdio.rs::dispatch` / `dispatch_async` are wrapped on the `Route::CallTool` arm only: `initialize`,
`tools/list` and `ping` are protocol housekeeping, and recording them would triple the event volume
for zero information. Each call emits `binary` (the server's own name), `name` (the tool),
`session_id` (`<binary>-<pid>-<process_start_ms>`), `status` from `ToolOutcome`, `input_summary`
(scrubbed, ≤ 512 bytes) and, when the tool is `miter` or `storypole`, `attributes`
`output_symbols_touched` / `files_referenced` taken from the response envelope it already builds.

### 5.3 CLI entry points (`SpanKind::CliCommand`)

One guard per process, opened in the binary's `main` after argument parsing (so the span name is the
subcommand, e.g. `miter.lookup`, not `miter`) and finished at the top-level `anyhow::Result`
boundary. Eight of eleven binaries already return a single `Result` from `main`, so this is one
binding and one `.finish_with_status(...)` per binary.

### 5.4 `outfeed gate` (`SpanKind::GateStep`)

`run_gate_steps` already loops over `Vec<GateStep>` and calls `execute(dir, &step.command)`. Each
iteration opens a child guard named `GateStep.name`, and `execute` sets on the spawned `Command`:

```rust
cmd.env("GAUGEBLOCK_TRACE_ID", &guard.trace_id)
   .env("GAUGEBLOCK_PARENT_SPAN_ID", &guard.span_id)
   .env("GAUGEBLOCK_TASK_KEY", ...);   // when inferable
```

so `cargo clippy`'s own nested `miter`/`chalkline` spans, and any MCP call made while the gate runs,
reparent onto the step. Skipped steps emit `SpanStatus::Skipped` with `duration_ms: 0` — a skip is
not a pass, which is the same distinction `GateStepResult::skipped` already makes.

### 5.5 `sawhorse` inference (`SpanKind::LlmInference`)

`RoleRouter::complete` and `complete_stream` emit one span per *attempt* (not per role), so a
fallback chain shows the failed provider and the provider that answered as siblings. `token_usage`
is copied from `InferenceResponse.token_usage` semantics already present
(`prompt_tokens`, `completion_tokens`, `model: model_used`); `reasoning_tokens` and the role go to
`attributes`. No provider implementation changes.

## 6. Training-capture enrichment (why three optional fields exist)

The observability dashboard needs thirteen fields. `rabbet`'s dataset builder needs three more, and
they are optional precisely so a successful span stays small:

| Field | Populated by | Purpose |
|:--|:--|:--|
| `input_summary` | `gaugeblock-mcp` (`McpTool`), CLI guard | what was asked, so a trajectory can be replayed without the raw arguments |
| `first_diagnostic` | `outfeed gate` (`GateStep`, `status == Error`) | the rejection reason that a repair must answer |
| `worktree_diff_hash` | `outfeed gate` (`GateStep`) | content address of the diff the step judged |

Capture rules:

1. **`input_summary` is scrubbed and capped at 512 bytes.** Scrubbing reuses `miter`'s existing
   literal redaction; the cap is applied to the *serialised compact* JSON, and truncation appends
   `…` so a downstream parser can tell "short" from "truncated". Over-long input is dropped rather
   than truncated mid-token, because half a JSON object trains nothing and confuses a reader.
2. **`worktree_diff_hash` = `sha256` of `git diff HEAD`** in the gate's working directory, computed
   once per gate run (not per step) and reused for every step span, so all failures in one run share
   an address.
3. **On failure**, the first actionable line of the step's own output (already reduced by
   `first_meaningful_line`) becomes `first_diagnostic`, and the scrubbed unified diff is written to
   `.gaugeblock/telemetry/snapshots/<worktree_diff_hash>.diff` — content-addressed, so re-running a
   failing gate rewrites the same file rather than growing the directory.
4. **On a later passing run of the same `(task_key, step_name)`**, the passing diff is snapshotted
   too. `Error(A) → Ok(B)`, `A != B`, is the `(rejected_diff, first_diagnostic) → chosen_diff`
   repair pair `GB-244` mines. **This ticket only guarantees the pair can be reconstructed**; it
   never writes a `SpoolEntry`.
5. A snapshot write is subject to the same fail-open rule as the span write. A missing snapshot
   degrades `GB-244`'s yield; it must never fail a gate.

## 9. Out of scope (deferred deliberately)

* **Retention, rotation, compaction.** `events.jsonl` grows without bound in this ticket. Rotating it
  is a separate decision (which spans survive?) and belongs in its own ticket, not smuggled into T3.
* **Mining or dataset emission.** `GB-244` owns `distill-telemetry`; this ticket guarantees the
  records and the snapshots exist, nothing more.
* **Typed MCP protocol migration** (`GB-235`) — orthogonal refactor of the same dispatcher.
* **Span-based alerting or budgets** in `benchwork` (e.g. "clippy p95 regressed"). Useful, needs the
  history first.
* **`AstPass` kind** is defined in the enum but emitted by nothing in this ticket; it exists so
  `miter`/`dado`/`batten` passes can be added without a schema bump.
* **A `benchwork-mcp` tool** exposing spans to an agent. Later.

| A telemetry bug breaks a gate | Fail-open is a test in T1, not a convention. The no-op guard returns the same value the caller had. |
| Span volume floods the daemon | MCP housekeeping methods are excluded; the broadcast channel for spans is separate from the 256-slot `LiveEvent` channel so a burst cannot evict a task update. |
| `gate/mod.rs` (224 LOC) crosses 250 | Extract `gate/steps.rs` before adding anything; the plan names the trigger explicitly. |
| The diff snapshot captures a secret | The snapshot is scrubbed by the same path as `input_summary`, and lives under a gitignored directory with a content-addressed name. |
| `benchwork-core` grows two dependencies for a feature it may not always ship | Both sit behind the same crate that already depends on eight suite crates; the tailer is one module and can be feature-gated if it ever needs to be. |
| Two processes write the same `events.jsonl` concurrently | `O_APPEND` plus a single `write_all` per line; a concurrent-append test with 4 writers asserts no interleaved line. |
