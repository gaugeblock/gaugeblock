# Task Plan: GB-217 — adopt `models-catalog` in sawhorse

> **Scope:** `sawhorse/crates/sawhorse-core` | **Depends on:** GB-218 (`models-catalog 0.1.0`, published)
> **Status:** Planned

## 1. What the crate gives us

`models-catalog 0.1.0` (repo `colinwolff/models-catalog`, MIT OR Apache-2.0, edition 2024, MSRV 1.85)
publishes both halves the suite needs, and they separate cleanly by feature:

* `CatalogSnapshot::bundled()` - a compile-time snapshot, **synchronous, no runtime, no network, no disk**.
* `catalog.get_model("provider", "id")`, `find_model("cline-pass/deepseek-v4.1-flash-1017")`,
  `resolve_default_model(provider, None)`, `provider_protocol(provider)`.
* `model.resolve_gateway_max_output_tokens(estimated_input, requested_max, reasoning_budget)` - the
  authoritative gateway budget: 32k cap, 1,024-token reserve, reasoning floor.
* `model.normalize_reasoning_effort(effort)` and `to_wire_reasoning_params(protocol, effort, max_out)` -
  per-protocol wire encoding.
* `ModelOverrides` applied via `with_overrides`, precedence `caller_override > local_settings > catalog >
  default` - the same order GB-215 wanted.
* `BillingTier` (`Subscription` / `Free` / `Credits`) and a `requires_streaming` flag from the curated
  overlay.

## 2. Dependency line (deliberate)

```toml
models-catalog = { version = "0.1.0", default-features = false, features = ["cline", "bundled"] }
```

**Do not enable `reqwest-client`.** Its default feature set pulls `reqwest 0.13` and `tokio`; sawhorse
is on `reqwest 0.12`, so the defaults would compile a second HTTP stack for a capability sawhorse
already has. `disk-spool` is likewise excluded: it adds `tokio` + `directories` and an ambient
`~/.cache/models-catalog` path, and the suite resolves its own directories. With
`default-features = false` the crate is a pure parser/lookup table, which is exactly what a
hermetic gate needs.

Freshness, when wanted, comes from running the crate's own CLI (`models-catalog sync`) outside the
library path and reading its spool - not from sawhorse doing HTTP.

Also avoid the crate's `~/.cline/data/settings/providers.json` reader: that is an ambient read and
callers must supply their own config.

## 4. Known gap this exposes

`gaugeblock_contracts::ReasoningEffort` has `None/Low/Medium/High`; the crate has those plus `XHigh` and
`Max`. Mapping is lossless in one direction only, so a caller cannot ask for `xhigh` until the contract
grows. That is a wire-contract change with its own `miter contracts` gate, so it is **GB-221**, not a
step here; step 5 maps our four values and downgrades the two it cannot express.

## 5. Out of scope

* Live refresh inside the library (see §2 - freshness is a CLI/spool concern).
* Replacing `ProviderConfig` (base URLs, auth env names, fallbacks) with crate provider specs. The crate
  carries protocol classification we may adopt in step 6, but config ownership stays with sawhorse.
* Any change to how `joiner` sizes a request: it calls `FillOptions`, and step 3 changes what sawhorse
  puts in it.

## 6. Measurement to record

Before/after on the payload for one fill: number of reasoning keys emitted (3 -> 1) and the wasted
round-trip count for a model flagged `requires_streaming` (1 -> 0). Both belong in the commit that
changes them.
