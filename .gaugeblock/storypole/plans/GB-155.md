## 1. Objective

Give the meta-harness its own release: a `suite.lock` pinning all eleven repositories, a root changelog
section, and an annotated `suite-v<version>` snapshot tag, behind a certified gate.

Current state (2026-10-28): the root has **no git remote**, **no `suite.lock`**, and one historical tag
`suite-v0.1.0-beta.2`, so the next snapshot derives as **`0.1.0-beta.3`**.

`outfeed release --suite` already implements the mechanics but has never run end to end.

2. Tier 3 matrix green across all eleven repos: `cargo fmt --all -- --check`,
   `cargo clippy --workspace --all-targets -- -D warnings`, `cargo nextest run --workspace`,
   `miter contracts`, `outfeed lockfiles`, `chalkline docs check --workspace`
   (expect `12 targets audited, 108 present, 0 missing, 0 drifted`).
3. `gaugeblock-contracts` and `gaugeblock-common` published at `0.1.0-beta.3`-independent version
   `0.1.0-beta.1` **before** any member that depends on them.
4. `suite.lock` generated and committed, pinning all eleven repositories with exact commits.
5. Root `CHANGELOG.md` gains an ecosystem section listing every member version.
6. Annotated tag `suite-v0.1.0-beta.3` on the root.
7. Decision on a root remote: `push_repo` cannot push a repository without one, and the harness
   history is currently single-copy on this machine.
8. Delete `outfeed/PERF_AUDIT_PLAN.md` once the release is out (it is a stray; its content lives in
   the ledger, the tickets, and the commit messages).

## 3. Runbook

```bash
# 0. Rebuild the tooling so the installed outfeed has lockfiles/override/waves.
cargo install --path outfeed/crates/outfeed-cli --force

# 1. Publish the foundation first (irreversible; crates.io rate-limits new crates).
outfeed publish common --dry-run      # packages both crates
outfeed publish common                # real upload; expect a 429 cooldown on the 2nd crate

# 2. Confirm the contracts are visible before members reference them.
for c in gaugeblock-contracts gaugeblock-common; do
  curl -s https://crates.io/api/v1/crates/$c | python3 -c \
    "import sys,json;print(json.load(sys.stdin)['crate']['max_version'])"
done

# 3. Release the members (11 repositories, common first because it is wave 0).
outfeed release --all --no-llm --dry-run   # inspect the plan table first
outfeed release --all --yes --no-llm

# 4. Meta-harness snapshot (writes suite.lock, root changelog, suite-v tag).
outfeed release --suite --suite-version 0.1.0-beta.3 --yes --skip-publish --skip-install

# 5. Push everything, including members that were clean before this pass.
outfeed push --all
```

## 4. Gotchas learned the hard way

* **`common` proposes the wrong version.** With no tag baseline the calculator overshoots to
  `0.1.0-beta.2`; use `outfeed release common --override-version 0.1.0-beta.1`. A second pass with the
  same override is a clean no-op (`already released as v0.1.0-beta.1`).
* **`outfeed release --all` must run from the harness root**; from inside a member it sees no members
  and reports "0 repositories".
* **A push failure is invisible on a re-run.** `release --all` self-heals only the registry half
  (`PublishPending`); a repo tagged locally but never pushed reports `Skip (Clean)` next time
  (`GB-153`). Check `git log origin/main..HEAD` per repo before declaring victory.
* **crates.io 429s quote the deadline in the body**, not a `Retry-After` header; `GB-140` handles it,
  but a three-attempt budget cannot outlast a 10-per-hour new-crate limit — space uploads out.
* **Never run two `storypole` mutations in parallel**: appends spliced two JSON events onto one line
  twice today. `GB-147` makes the append atomic, but keep mutations serial until it is trusted.
* **`git add <dir> Cargo.lock` aborts staging entirely in a repo that ignores it**, and
  `git commit -q` then fails silently (`GB-150`). All eleven repos now track a fresh lockfile.
