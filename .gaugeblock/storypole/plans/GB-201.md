# Task Plan: GB-201 — purge the declared-but-unreferenced dependencies

> **Scope:** every repository's `Cargo.toml` | **Parent:** `GB-200` (Phase 1a) | **Status:** Analysed, not started
>
> **Precondition, unresolved:** the machine has **113 MB free** (100% of 234 GB). A purge edits
> manifests in 9 repositories and needs a validation build per crate. A warm `cargo check -p` costs
> about 2 MB, so the work is possible, but a single unexpected rebuild would hit ENOSPC mid-gate and
> leave a repository in a state that fails `git bisect`. Free space, then start.

## 1. The measurement

`miter deps --path . --unused` reports **62** declarations across 24 crates (rabbet-cli 5, dado-cli 4,
dado-mcp 4, rabbet-core 4, then 3s and 2s down to five crates with 1). The baseline rose from 59 to 62
when GB-199 stopped counting fixture strings as proof of use - a scan that over-counts use
under-counts dead weight, so the two moved together.

## 2. First pass (superseded by 2b - it used a non-word-boundary grep)

Classifying all 62 against source, tests, `build.rs` and feature tables shows the scan cannot
distinguish four cases, and three of them must not be deleted:

| Class | Count (approx) | Treatment | Example |
|:--|:--|:--|:--|
| Used only under `#[cfg(test)]` | 12 | **move to `[dev-dependencies]`** | `batten-mcp -> serde` (only `tests/mcp_test.rs`), `chalkline-core -> tokio`/`tracing` (only `tests/core_t*`), `dado-core -> uuid` |
| Optional feature dependencies | 3 | **keep, writing the reason** | `sawhorse-core -> candle-core`, `candle-nn`, `candle-transformers` are `optional = true` and gated behind the `candle` feature |
| Mentioned only in a stripped context | 6 | remove | `sawhorse-cli -> serde` appears in `commands/models.rs` only inside text the scanner strips |
| Genuinely dead | 40 | remove | `batten-core -> regex` (nothing in `src/`), `rabbet-cli -> miter-engine`/`dado-core` (no reference anywhere), `benchwork-core -> async-trait`/`futures` |

The dev-dependency class is the trap: deleting it compiles fine and breaks the test suite, and the
breakage only appears on a machine that runs `cargo nextest`. Moving the declaration keeps the tests
green and shrinks the shipped dependency graph, which is the actual goal.

Each removal needs one of: a written reason (feature, derive-only, build script) or deletion with the
site check repeated afterwards (`miter deps --why <crate>`) so `--unused` counting zero is not an
artifact of a fresh mis-scan.

## 2b. Corrected classification (2026-10-30, after a false start)

The first pass in section 2 above used a **non-word-boundary** grep, so `serde_json` matched "serde" and
every CLI/MCP crate looked like it used serde. Redone with `grep -rnw` across `src/`, `tests/` and
`build.rs` of each crate, the real split is:

| Class | Count | Treatment |
|:--|:--|:--|
| No reference anywhere (word-boundary) | **49** | remove |
| `optional = true` feature deps | **3** | keep with a written reason (`sawhorse-core` candle trio) |
| Has a reference the scan strips | **10** | 7 of them are test-only -> move to `[dev-dependencies]`; the rest are string literals or real src uses -> keep |

The 10 with references, individually: `batten-core/regex`, `rabbet-core/parquet`, `outfeed-core/semver`,
`dado-core/tracing`, `dado-core/uuid` are **used in tests only** (move to `[dev-dependencies]`).
`chalkline-core/tokio` and `chalkline-core/tracing` are matched inside a **string literal** in
`tests/core_tests.rs` (a fixture manifest), so they are genuinely unused. `dado-mcp/serde` matches a
JSON description string in `src/schema.rs`. `miter-engine/hcl` and `outfeed-core/reqwest` need a
manual look before acting.

## 2c. Ready to apply (evidence collected, gate incomplete)

These nine removals were applied and reverted in the same session: `cargo clippy --all-targets -D
warnings` was green for `joiner-cli`, `joiner-mcp` (both crates) with the declarations removed, but the
`cargo nextest` run had not finished when the session ended, so the edits were reverted rather than
committed against an incomplete Tier 2 gate.

```
joiner/crates/joiner-cli/Cargo.toml   serde, thiserror
joiner/crates/joiner-mcp/Cargo.toml   serde, thiserror, uuid
outfeed/crates/outfeed-cli/Cargo.toml serde
outfeed/crates/outfeed-mcp/Cargo.toml serde, thiserror
outfeed/crates/outfeed-core/Cargo.toml uuid
```

Each has zero word-boundary references in `src/`, `tests/` and `build.rs`, and each crate's clippy run
after removal was clean. Re-apply, then run per repo:
`cargo clippy -p <crate> --all-targets -- -D warnings`, `cargo nextest run -p <crate>`,
`outfeed lockfiles`. Expect a long build: removing a dependency from a `-mcp` crate invalidates the
feature graph and cargo re-checks the whole tree, which is what ran past the session budget.

## 2d. Disk

had failed earlier purely on `InsufficientDiskSpace`. Confirm headroom before any full-workspace run.

2. The `-mcp` and `-cli` serde entries - the dev-dependency moves, smallest blast radius, 8 crates.

5. Re-run `miter deps --path . --unused`: target is zero, and the count must be zero for the right

## 4. Gates

Per commit: `cargo fmt --check -p <crate>`, `cargo clippy -p <crate> --all-targets -- -D warnings`,
`cargo nextest run -p <crate>`, and `outfeed lockfiles` for the touched repository. Tier 3 at the end
of each repository, not at the end of the ticket: a manifest change that lands with a broken sibling
crate is the failure mode this ordering exists to prevent.

## 5. Recorded findings

* The scan over-reports by roughly 15 of 62 because it strips test code, which is correct for
  "is this imported at runtime" and wrong for "is this declaration needed".
* `sawhorse-core`'s candle trio are optional feature dependencies; they are the plan's named
  exception and should be commented rather than removed.
* Disk headroom is the binding constraint, not the code.
