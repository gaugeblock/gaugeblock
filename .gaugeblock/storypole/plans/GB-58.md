# GB-58: Multi-Repo Storypole Rollout and Task Distribution across Suite Repositories

> **Status:** Ready  
> **Target Scope:** `workspace` (all 10 member repositories)  
> **Key Invariants:**  
> 1. Standalone Autonomy: Every repository must have its own `.storypole/` committed to Git with its canonical prefix.  
> 2. Zero Working Tree Pollution: Each member repository must be cleanly versioned without untracked files.  
> 3. Traceability: Scoped tasks and plans must be properly preserved during migration.  
> 4. Non-breaking: Root workspace ledger retains workspace-level and cross-cutting epics.  

---

## 1. Executive Summary & Rollout Strategy

With `GB-57` having delivered the multi-repo engine capabilities to `storypole`, `GB-58` executes the staged rollout across the 10 member repositories:
1. Initialize and commit `.storypole/` configurations in each member repository with its canonical prefix:
   * `batten`: `BA`
   * `benchwork`: `BW`
   * `chalkline`: `CH`
   * `dado`: `DA`
   * `joiner`: `JN`
   * `miter`: `MTR`
   * `outfeed`: `OF`
   * `rabbet`: `RB`
   * `sawhorse`: `SH`
   * `storypole`: `SP`
2. Distribute scoped tasks from the meta-harness root ledger into their respective repository ledgers.
3. Migrate attached design plans (`plans/*.md`) to member repositories.
4. Verify workspace rollups and standalone CLI operations across all 10 repositories.

## 2. Execution Steps

### Step 1: Stage and commit local `.storypole/` configuration in each member repository
* In each of the 9 remaining member repositories, initialize `.storypole/config.toml`, `.gitignore`, and `ledger.jsonl`.
* Commit cleanly in each repository's Git history: `chore(storypole): initialize local backlog store with prefix <PREFIX>`.
* *Verification Gate:* `for d in batten benchwork chalkline dado joiner miter outfeed rabbet sawhorse storypole; do (cd $d && storypole list); done`

### Step 2: Distribute scoped tasks from root ledger to member repositories
* Run `storypole workspace distribute` to partition tasks by `scope.repo`.
* *Verification Gate:* Tasks appear in their respective member repositories.

### Step 3: Migrate associated design markdown plans to member repositories
* Copy corresponding design plans from `.gaugeblock/storypole/plans/` into `<repo>/.storypole/plans/`.
* Commit plan assets to the respective member repositories.
* *Verification Gate:* `storypole plan show <KEY>` resolves from within member repositories.

### Step 4: Full workspace rollup audit and clean git status check
* Verify `storypole workspace list` reports initialized stores with accurate task counts.
* Verify `git status` across all 10 repositories and meta-harness root is completely clean.
* *Verification Gate:* `git status -s` is clean across all 10 repos.
