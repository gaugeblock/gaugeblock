# Task Plan: GB-129 — Bootstrap gaugeblock/common and Extract gaugeblock-contracts for CONTRACTS.md

> **Task Key:** `GB-129`  
> **Parent Epic:** `GB-128`  
> **Scope:** `workspace`  
> **Status:** Planned

---

## 1. Problem Statement
Currently, downstream crates (`chalkline`, `dado`, `batten`, `joiner`, `benchwork`, `outfeed`) link monolithic `-core` engines (`storypole-core`, `sawhorse-core`, `miter-engine`) merely to access shared wire types defined in `CONTRACTS.md`. This transitively pulls in bundled C SQLite, reqwest/rustls, and tree-sitter grammars into every downstream crate's build and publish cycle.

---

## 2. Technical Blueprint
1. Create `common/` workspace repository with `crates/gaugeblock-contracts`.
2. Extract pure serde wire types matching `CONTRACTS.md`:
   * `miter`: `Language`, `SymbolBinding`, `LexicalScope`, `VerificationReport`
   * `storypole`: `Task`, `TaskKind`, `TaskScope`, `StorypoleConfig`, `DecisionRecord`
   * `sawhorse`: `InferenceRequest`, `InferenceResponse`, `ModelRole`
   * `outfeed`: `ReleasePlan`, `CommitInfo`, `BumpType`, `SuiteLock`
   * `dado` & `batten`: `PatternDeclaration`, `GrammarSpec`, `TokenMask`
3. Map `gaugeblock-contracts` in `.cargo/config.toml` `[patch.crates-io]`.
4. Repoint downstream crates to consume `gaugeblock-contracts`.

---

## 3. Execution Steps
* **Step 1:** Scaffold `gaugeblock/common` workspace and `gaugeblock-contracts` crate.
* **Step 2:** Port wire types from `CONTRACTS.md` with pure serde derivations.
* **Step 3:** Repoint downstream crates and verify with `cargo check --workspace`.
* **Step 4:** Tier 3 workspace verification (`cargo nextest run --workspace`).
